# 第一阶段开发计划（不使用 Qwen）

## 模型决定

- 项目禁止调用 `qwen2.5:7b-instruct`。
- 默认主链路不依赖任何生成式本地模型，使用证据保真分析模式。
- DeepSeek 等云模型只是可选增强能力，不是主链路依赖；必须经过资料密级、单次授权和审计检查。
- `bge-m3` 只承担本地语义向量生成，不参与知识结论生成，并且保持可选。关闭后仍可使用 SQLite 全文检索。
- 未来如需接入新的本地分析模型，必须由用户另行确认，不能自动选择或静默回退。

## 已完成：同文档内证据多定位合并

- `faithful-schema-v2-multilocator` 只处理同一文档版本和同一处理运行内逐字相同的正文；近似文本不合并，确保每个定位均可逐字回到原文。
- 保留一条规范证据正文和首定位兼容字段，全部有序位置写入 Schema v8 `evidence_locations`；分析 JSON、JSONL、Wiki、标注候选、CLI 和 Web 详情均可查看多定位。
- 原始文件、解析单元、历史证据、审核状态和既有引用永不删除或改写；迁移只为历史证据回填已有首定位。
- 跨文档、跨文件版本和跨处理运行相同内容不自动合并，以免混淆来源、密级与适用范围。
- 新策略通过显式 `ingest --reprocess` 生效并沿用既有重处理审计；旧运行完整保留，向量索引会按证据指纹识别为过期。

## 已完成：人工实体规范化与模型候选裁决基础层

- Schema v9 新增规范实体、同类型唯一别名和证据实体提及三张表；规范名称自动成为不可移除的 canonical 别名。
- 名称和别名只做 NFKC、大小写折叠与空白归一，不做简称猜测、后缀删除或相似文本自动合并；一名多指必须由人工先选择实体类型和规范实体。
- 新关联只能写入当前文件版本与当前处理运行的证据，提及必须逐字存在于证据原文并匹配已登记别名；历史关联保留，但历史证据不能新增关联。
- CLI 支持创建、列表、详情、别名增删、证据关联和解除；所有写操作要求 actor，审计只记录实体/别名 ID、密级和名称或提及 SHA-256，不复制正文。
- Lint 检查 canonical 别名唯一性、规范名称归一结果，以及每个实体提及能否逐字回到证据并匹配别名。当前真实工作区保持0个规范实体和0条关联，等待人工建档，不从 DeepSeek 输出自动灌入。
- Schema v10 将 `model_assisted` 分析中的 `entities[]` 作为独立候选导入，不读取 concepts/projects，不触发云调用，也不直接创建规范实体。导入重验分析 Schema、当前文件版本、SHA-256、密级、当前处理运行和逐字证据映射；同一分析文件重复导入幂等。
- 候选状态固定为 `pending → accepted/rejected`。接受必须由人工选择现有 active 规范实体；系统再次检查来源仍为当前、候选名称逐字存在，并在同一事务内登记无歧义别名、创建证据关联、固化终态和审计。非逐字候选、过期候选和别名冲突均不能接受。
- 驳回意见必填但只保存 SHA-256；接受与驳回都是不可重复裁决的终态。Lint 进一步检查候选归一结果、逐字标记，以及 accepted 候选是否真的存在对应别名和证据关联。真实工作区迁移后保持0条候选，不会自动导入此前的 DeepSeek 产物。
- Schema v11 增加人工实体合并请求：提议人显式选择同类型源实体与目标实体并填写说明，请求直接进入 `reviewing`，只能由不同 actor 批准或驳回；系统不运行名称相似度、不自动创建合并候选。
- 批准合并会在单一事务中迁移源实体全部别名、证据提及及已接受模型候选指向，再将源实体归档；旧实体 ID 与源目标方向保留，证据正文和原始关联时间不改写。提议与复核意见仅保存 SHA-256，类型/状态/唯一性或外键检查失败时整体回滚。
- CLI 已提供 `merge-propose`、`merge-list` 和 `merge-review`；Web 已开放同类型可见实体的定向提议、待复核搜索分页、必填意见、异人批准/驳回和绑定请求 ID 的批准确认短语。列表与写接口分别重算源目标实体的历史最高密级，伪造 restricted、unclassified 或 archived ID 会被阻断；最终迁移仍复用核心事务。Lint 验证异人复核、合并请求类型、归档源实体的零别名/零提及/零候选残留，以及 active 实体 canonical 别名完整性。
- `merge-candidates` 已提供只读确定性相似候选：仅比较 active 同类型实体与人工别名，以三字符片段阻塞后计算最佳别名相似度；高频块上限50个实体、比较硬上限50,000对，结果显式报告跳块和截断。候选不落库、不写审计、不自动提交合并；当前 Web 合并提议仍由人工明确选择方向，不把相似度投影视为事实。
- 实体可见密级由全部历史证据提及实时取最高资料密级，不增加可手工降级的实体密级字段；restricted 历史支持不会随版本变化退出，零证据实体标记为 `unclassified`。Web 候选列表只提供 public/internal/confidential active 实体，写接口按目标 ID 再次重算并阻断 restricted、unclassified 和 archived；CLI `visibility-list` 可查看完整投影。

## 已完成：人工业务关系基础层

- Schema v12 用关系类型、关系和证据关联三张表保存业务语义，不把共现边、名称相似度或模型候选当成事实。关系类型由人工登记为有向或无向；无向端点按实体 ID 规范化，重复 active 关系受唯一索引阻断。
- 登记关系必须选择两个 active 实体和至少一条当前 verified 证据；每条证据必须已有两个端点的人工逐字提及。登记与撤销均要求 actor 和必填说明，正文只保存 SHA-256；`active → retracted` 后保留端点和全部证据历史，可在新适用期另建新 ID。
- `graph business` 只投影仍有当前 verified 非 restricted 支撑的 active 关系，旧版本、状态退回和 restricted 支撑不会进入安全图，但历史关系不被删除。Lint 检查端点、类型、双端提及和支撑完整性，并将失去当前 verified 支撑标为待复核 warning。
- 业务关系历史引用的实体提及不可解除；实体合并也不会迁移或改写旧关系，源实体一旦存在任何 active/retracted 关系历史就会阻断批准。Web 已开放可见关系列表、共同 verified 非受限证据选择、强确认登记和强确认撤销；列表与写接口双重重算实体密级和证据资格，不返回候选证据原文。关系类型仍由 CLI 管理；后续需要显式设计“实体身份替代”语义后才能放宽合并，并继续完成路径 Web 探索和图谱质量评测。
- `graph paths` 在业务关系安全投影上以确定性 BFS 查询1到4跳简单路径。默认只走有向边正向，无向边可双向，反向遍历有向边必须显式指定；每跳返回原关系方向、遍历方向和合格证据 ID，路径返回证据并集与各跳共同证据。结果数、候选边和扩展次数均有硬上限并报告截断；多跳连通性明确不构成新的业务关系或事实结论。
