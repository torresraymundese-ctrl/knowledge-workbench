# 第一阶段开发计划（不使用 Qwen）

## 模型决定

- 项目禁止调用 `qwen2.5:7b-instruct`。
- 默认主链路不依赖任何生成式本地模型，使用证据保真分析模式。
- DeepSeek 等云模型只是可选增强能力，不是主链路依赖；必须经过资料密级、单次授权和审计检查。
- `bge-m3` 只承担本地语义向量生成，不参与知识结论生成，并且保持可选。关闭后仍可使用 SQLite 全文检索。
- 未来如需接入新的本地分析模型，必须由用户另行确认，不能自动选择或静默回退。

## 已完成：同文档内证据多定位合并

- `faithful-schema-v2-multilocator` 只处理同一文档版本和同一处理运行内逐字相同的正文；近似文本不合并，确保每个定位均可逐字回到原文。
- 保留一条规范证据正文和首定位兼容字段，全部有序位置写入 Schema v8 `evidence_locations`；分析 JSON、JSONL、Wiki、标注候选、CLI 和 Web 详情均可查看多定位。
- 原始文件、解析单元、历史证据、审核状态和既有引用永不删除或改写；迁移只为历史证据回填已有首定位。
- 跨文档、跨文件版本和跨处理运行相同内容不自动合并，以免混淆来源、密级与适用范围。
- 新策略通过显式 `ingest --reprocess` 生效并沿用既有重处理审计；旧运行完整保留，向量索引会按证据指纹识别为过期。
