# 第一阶段开发计划（不使用 Qwen）

## 模型决定

- 项目禁止调用 `qwen2.5:7b-instruct`。
- 默认主链路不依赖任何生成式本地模型，使用证据保真分析模式。
- DeepSeek 等云模型只是可选增强能力，不是主链路依赖；必须经过资料密级、单次授权和审计检查。
- `bge-m3` 只承担本地语义向量生成，不参与知识结论生成，并且保持可选。关闭后仍可使用 SQLite 全文检索。
- 未来如需接入新的本地分析模型，必须由用户另行确认，不能自动选择或静默回退。

## 单文件链路的 Web 开发门槛

- [x] 原始文件不被修改，并保存内容寻址只读副本。
- [x] 每条证据可以回到文件版本和文档内定位。
- [x] 无模型模式下 Wiki 只整理原文证据，不生成无依据结论。
- [x] 重复导入不会重复创建知识。
- [x] 极性或数值变化的相似原子证据进入冲突队列，且不会自动覆盖正式知识。
- [x] 失败任务能够通过持久化队列自动重试和恢复。
- [ ] 在真实试点资料上验证更多语义冲突类型的召回率。
- [ ] 严格 JSON Schema 输出在试点资料上保持稳定。
- [x] 当前证据和页面状态可人工审核。
- [x] Wiki 出链和反链写入 SQLite，并生成 Obsidian `[[链接]]`；已发布修订不可静默修改。
- [ ] 完成 10–20 份真实试点资料的输出质量评测。

只有所有未完成门槛通过后才开始 Web 页面开发。BGE-M3 是否启用不作为 Web 开发的硬性门槛。
