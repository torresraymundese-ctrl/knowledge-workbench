# 第一阶段开发计划（不使用 Qwen）

## 模型决定

- 项目禁止调用 `qwen2.5:7b-instruct`。
- 默认主链路不依赖任何生成式本地模型，使用证据保真分析模式。
- DeepSeek 等云模型只是可选增强能力，不是主链路依赖；必须经过资料密级、单次授权和审计检查。
- `bge-m3` 只承担本地语义向量生成，不参与知识结论生成，并且保持可选。关闭后仍可使用 SQLite 全文检索。
- 未来如需接入新的本地分析模型，必须由用户另行确认，不能自动选择或静默回退。

## 单文件链路的 Web 开发门槛

- [x] 原始文件不被修改，并保存内容寻址只读副本。
- [x] 每条证据可以回到文件版本和文档内定位。
- [x] 无模型模式下 Wiki 只整理原文证据，不生成无依据结论。
- [x] 重复导入不会重复创建知识。
- [x] 极性或数值变化的相似原子证据进入冲突队列，且不会自动覆盖正式知识。
- [x] 失败任务能够通过持久化队列自动重试和恢复。
- [ ] 在真实试点资料上验证更多语义冲突类型的召回率。
- [ ] 严格 JSON Schema 输出在试点资料上保持稳定。
- [x] 当前证据和页面状态可人工审核。
- [x] Wiki 出链和反链写入 SQLite，并生成 Obsidian `[[链接]]`；已发布修订不可静默修改。
- [ ] 完成 10–20 份真实试点资料的输出质量评测。

只有所有未完成门槛通过后才开始 Web 页面开发。BGE-M3 是否启用不作为 Web 开发的硬性门槛。

## 真实试点基线（2026-07-21）

- 试点副本只保存在 `workspace/`，统一标记为 `internal`，未调用任何云模型。
- 10 份资料全部保存 SHA-256 和只读副本；重复导入能够按内容哈希跳过。
- 7 份 DOCX 和 3 份旧 `.doc` 均完成导入、原子证据和 Wiki 草稿链路；`.doc` 默认拒绝，只有单次显式授权才调用本机 Word。
- 3 份旧 `.doc` 共生成 609 条原子证据；转换后无残留 Word 进程或临时目录，原始内容寻址副本保持只读。
- `.doc` 证据定位已记录 Microsoft Word 版本 `16.0.19127.20302` 和临时 DOCX 的 SHA-256，评测命令沿用同一显式授权边界。
- 当前证据读取增加双重边界：文档当前版本与该版本当前处理运行；历史证据不能重新进入审核或发布。
- 新文件版本或新处理运行会将本页及已发布下游引用页标记为 `needs_revalidation`，旧正式修订在复核完成前继续有效。
- 10 份试点资料已生成 154 条均匀分布的标注候选；候选不等于黄金答案，仍需人工回源确认。
- 正式评测会拒绝未填写占位模板、无必要证据和重复必要证据，且在启动文档解析前失败。
- 冲突检测已排除纯版本号、发布日期和条款编号变化，并以序号邻域和稳定签名阻塞替代全量笛卡尔比较。
- 首次真实工作区Lint结果：11个当前版本、11个当前run、1324条当前证据，0错误；迁移前样例缺少当时尚不存在的分析/生成产物，保留2项警告且不伪造。
- Schema v6 已加入可审计黄金标注会话与逐用例复核；创建者选择证据并提交，另一位审核人必须逐项记录决定后才能批准，来源或密级变化会阻断旧标注导出。
- 冲突评测已建立独立Schema和CLI；内置8例合成基线包含5个真冲突与3个非冲突，当前精确率、召回率和类型准确率均为1.0，真实冲突对仍待人工补充。
- 结论引用增加保守文本关联检查：引用真实ID但内容完全无关会被阻断，低支持结论进入评测指标；无模型保真模式明确报告结论数为0，不虚报结论正确率。
- 引用支撑增加独立Schema、CLI和11例合成黄金样例；0.15以下硬阻断，0.15至0.25进入人工复核；方向、关键数字和混引矛盾证据均纳入检查，当前合成基线精确率与召回率均为1.0。
- 实测暴露出 Word 表格未进入证据层的问题；DOCX 解析器 v2 已修复，并增加真实表单回归验证。
- SQLite Schema v4 已加入 `processing_runs`；同一文件版本可通过 `ingest --reprocess` 创建新版派生证据和 Wiki 草稿，旧结果保留且不参与默认检索。
- 7 份 DOCX 已完成 v1→v2 真实重处理：文件版本数保持不变，重复执行能够按处理指纹跳过，并写入完整审计事件。
