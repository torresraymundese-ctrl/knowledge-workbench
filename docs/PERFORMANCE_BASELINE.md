# 本地性能基线

测试日期：2026-07-21

## 环境

- Windows，Python 3.13.13
- CPU：AMD Ryzen 7 5700U（8 核 16 线程）
- 内存：约 16 GB
- 无 CUDA，按 CPU 推理
- Ollama `bge-m3:latest`
- 向量维度：1024，`float32`，归一化后精确余弦搜索

## 首次实测

真实样例包含 4 条中文原子证据：

| 指标 | 结果 |
|---|---:|
| 4 条证据首次批量嵌入 | 7.635 s |
| 索引文件写入 | 0.005 s |
| 热查询向量生成中位数 | 457.23 ms |
| 1000 中文字符向量生成 | 3183.44 ms |
| 当前 4 条向量搜索中位数 | 2.23 ms |
| 500 × 1024 合成向量矩阵 | 1.95 MiB |
| 500 条精确搜索中位数 | 0.340 ms |

命令：

```powershell
.\.venv\Scripts\knowledge.exe index build --model bge-m3
.\.venv\Scripts\knowledge.exe benchmark --iterations 3 --synthetic-count 500
```

## 结论

500 条规模的向量搜索和内存不是瓶颈，主要耗时来自 BGE-M3 在 CPU 上生成向量。摄入应采用批处理和增量索引，查询向量需要缓存；引入 Qdrant 不能解决模型推理耗时，因此当前阶段继续使用可审计的 NumPy 精确检索。

本次 500 条结果是搜索层合成基线，不等同于 500 页真实文档的端到端摄入测试。拿到首批资料后仍需测量解析、真实批量嵌入、峰值内存和检索质量。
