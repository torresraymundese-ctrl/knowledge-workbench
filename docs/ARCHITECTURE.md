# 第一阶段架构

## 目标

当前版本建立一个安全、可验证的知识编译内核。它不是 Obsidian 插件，也不依赖 Web 界面；未来的 Web 工作台和 Obsidian 都只通过同一业务层读取或修改状态。

## 数据流

```text
用户文件
  -> SHA-256 去重与版本识别
  -> workspace/raw/ 内容寻址只读副本
  -> 格式解析器（保留页码/标题/单元格/幻灯片/行号）
  -> 原文保真分段器（同一运行内逐字相同正文合并为多个定位）
  -> processing_runs 派生运行（解析器+版本+提取方法）
  -> SQLite 原子证据 + JSONL 可检查镜像
  -> Obsidian 兼容 Markdown Wiki 草稿
  -> 人工证据审核
  -> 页面修订审核与发布
  -> SQLite FTS5 + BGE-M3 精确余弦检索
```

## 当前安全性质

- 同一 SHA-256 不会重复创建文件版本或 Wiki 页面。
- 解析器或提取器升级时创建版本化派生运行；相同处理指纹不会重复执行，旧证据和旧修订保留审计。
- 全文检索、审核列表和向量索引只读取“文档当前版本 + 该版本当前处理运行”的证据；冲突检测可显式比较新旧版本的当前处理运行。
- 语义检索会校验当前证据指纹；派生运行变化后拒绝使用旧向量索引，直到显式重建。
- 历史文件版本或已被替代处理运行的证据和 Wiki 修订不能进入审核或发布状态。
- 文件版本或处理运行变化时，旧正式修订继续生效，但本页及引用它的已发布下游页面自动标记 `needs_revalidation` 并写入审计。
- 导入事务失败时会回滚数据库并清理本次生成的文件。
- 旧 `.doc` 默认拒绝处理；显式授权后只在临时目录转换，宏被禁用，证据定位保存转换工具、版本和转换产物哈希。
- 原文片段为空时数据库约束和业务逻辑都会阻断。
- Schema v8 以 `evidence_locations` 保存证据的全部有序来源定位，并以 `evidence.locator_json` 保留首定位兼容读；合并只发生在同一处理运行内逐字相同的正文，跨文档、跨版本和近似文本不合并。迁移只回填历史首定位，不改写证据 ID、审核状态或既有引用。
- Schema v9 以 `canonical_entities`、`entity_aliases` 和 `evidence_entity_mentions` 保存人工确认的实体规范化结果。同类型的规范化别名全局唯一；关联提及必须逐字存在于当前证据原文且匹配已登记别名。模型语义字段不会自动创建实体或合并别名，所有写操作要求 actor 并记录不含名称正文的哈希审计；错误关联可解除，历史关联随旧证据保留但不能向历史证据新增关联。
- `draft` 证据不能跳过 `reviewing` 直接变成 `verified`。
- 页面发布前必须至少引用一条证据，且所有引用证据都是 `verified`；核心发布函数在事务内再次校验 Markdown 路径和内容哈希。
- 已发布页面的新资料生成新修订，不覆盖当前已验证修订。
- `internal` 云调用需要单次授权；更高密级无条件禁止云调用。
- 模型调用审计只保存模型、密级、耗时和输入输出哈希，不保存提示词明文。
- 阶段二不能仅用一个真实证据ID包装无关结论；结论与全部所引原文均缺乏最低文本关联时Schema校验阻断，弱关联继续交给人工复核；高相似引用中的方向或关键数字矛盾同样阻断。
- DeepSeek 阶段二 `wiki-generation-v2-extractive` 提示词只允许单条证据的逐字抽取式结论，禁止改写、多证据综合及原文未明确陈述的因果、主体、条件、时间、范围、义务、许可、禁止、比较或数值推断；无法逐字表达的内容进入人工任务。该提示词约束不替代阶段二既有的 Schema、引用 ID、文本支撑、方向词和关键数字硬校验。
- DeepSeek 阶段一 `analysis-v3-source-anchored` 不让模型决定证据身份、正文或定位。本地先用 `FaithfulEvidenceExtractor` 生成有序 `candidate_id`、逐字 excerpt 和全部定位，模型只对这份固定清单补充证据类型、实体、概念、项目和适用范围；返回后本地按 `candidate_id` 强制覆盖 excerpt、首定位和 `locators[]`，未知 ID 直接阻断。因此模型改写正文或伪造、遗漏、删减定位均不会进入分析产物，表格、段落、`unit`、`segment` 和同文多位置只来自确定性解析层。
- 新旧版本出现允许/禁止方向或关键数值变化时按证据对进入冲突队列。
- 跨文档冲突候选只用于构建人工质量基线，不自动写入冲突队列或改变证据状态。候选包排除 `restricted`，只能写入 `workspace/evaluations/` 且不得覆盖；候选身份不包含可编辑标签和复核字段。标签提交和固化都会重查当前文件版本、当前处理运行、原文、密级、文档元数据和全部定位；固化还校验已审计标签摘要、完整候选集和标注/复核人员分离。
- 任务租约绑定 `lease_owner`；非领取者不能续租、完成或报告失败，过期领取者也不能迟交结果。长任务由心跳续租；工作者失联后，过期租约会清除所有者并回到重试队列，达到最大次数才进入 `failed`。
- 持续工作器空闲轮询采用有上限的指数退避，收到停止信号后等待当前任务完成；启动、停止原因和本次处理统计写入审计。租约续期失败时工作器停止领取新任务，避免在失去所有权后继续并发处理。

## 存储真相

- SQLite 是业务状态、审核状态和审计状态的唯一真相。
- `workspace/raw/` 是内容寻址的来源副本。
- `workspace/evidence/*.jsonl` 按派生运行保存，便于人工检查和迁移，不负责状态流转。
- 分析 JSON、证据 JSONL、Wiki 草稿、标注候选和 Web 详情均投影全部定位；`lint` 同时验证定位非空、序号连续、首定位兼容字段、分析/镜像一致性、规范实体 canonical 别名，以及实体提及能否逐字回到证据原文。
- `workspace/wiki/` 是 Obsidian 可读产物；手动编辑需要在后续里程碑加入回写和差异保护。
- `workspace/index/` 是可重建派生数据，可随时由 SQLite 证据重新生成。
- `workspace/evaluations/` 保存可重复比较的质量评测报告。
- `labeling-pack` 只从当前证据生成均匀分布的人工定位候选，不会自动把系统输出认定为黄金答案。
- `lint` 对现代处理运行执行严格产物验收；迁移前尚不存在的分析/生成产物显示为可见警告，不会使用来源不一致的文件冒充通过。
- Schema v6 将黄金标注保存为 `draft → reviewing → approved` 状态；提交人与复核人必须不同，每个用例均需由最终批准人逐项通过，批准后才能导出正式评测集。
- 标注证据必须属于当前文件版本和当前处理运行；来源文件、密级或处理状态变化会使未导出的标注失效。
- 冲突评测报告只输出用例ID、预期/预测类型和指标，不复制旧证据与新证据原文；真实内部冲突数据集应保存在 `workspace/`。
- 跨文档候选使用稳定字符片段阻塞后再计算文本相似度，避免直接全量笛卡尔比较；候选包同时保留预测为冲突和相似但未判冲突的证据对，供人工标注真阳性与负例。被 `--limit` 截断的包不能固化为完整召回率基线。
- Web 列表 API 不返回来源路径、原始副本路径、评测集路径、证据原文或通用审计详情；审核队列按证据、冲突和 Wiki 修订独立分页，各队列只接受自身有效状态，并只按安全元数据筛选和搜索；`restricted` 原文件名与页面标题不参与搜索。单条证据原文只在显式详情请求中返回，`restricted` 名称、定位、原文和状态写入始终阻断。
- `rejected` Wiki 修订不重新进入待办队列；独立只读历史投影可展示非受限修订的领域复核意见、操作者、驳回时间及来源是否仍为当前版本，但不返回 Markdown、文件路径或原始审计详情，也不提供任何重新流转操作。`restricted` 历史标题和复核意见脱敏。
- Web 证据、冲突与 Wiki 修订提交、驳回和正式发布操作必须提供 actor，并使用进程级 CSRF 令牌、JSON Content-Type、同源和 Host 校验；业务写入只委托给 `review.py` 与 `conflicts.py` 状态机，继续产生原有审计事件。Wiki 修订操作前额外校验当前文件版本、当前处理运行和 Markdown 内容哈希；外部未同步编辑必须阻断。`reviewing → rejected` 必须附带复核意见，驳回新修订不改变旧正式修订。Web 正式发布还要求非 `restricted`、至少一条引用、引用全部验证、预览覆盖全文，并完整输入绑定修订 ID 的确认短语；后端重新计算资格，截断预览的长修订只能经 CLI 发布。
- Web 跨文档候选服务按 `pack_id` 在 `workspace/evaluations/` 发现通过 Schema 与身份校验的候选包，不向浏览器返回文件路径。详情读取和每次写入均重验当前证据来源；写入还在进程锁内比较客户端所见文件 SHA-256，原子替换 JSON，并在审计失败时恢复原内容。标签摘要一经提交即锁定，若文件标签与最新提交摘要漂移则整个 Web 写链路阻断；只有不同 actor 可复核，驳回意见必填。逐项审计保存候选 ID、决定、文件前后哈希和意见哈希，不保存原文或意见正文。Web 不自动创建业务冲突，也不固化最终评测集。
- Web 服务只允许监听 `127.0.0.1` 或 `localhost`，拒绝非本机 Host 以防 DNS rebinding；静态页面不调用外部 CDN，并设置 CSP、禁止嵌入、禁止缓存和禁止引用来源泄露等响应头。

## 尚未实现

- DeepSeek 抽取式提示词已通过短 Markdown 和34单元表格 DOCX；本地证据锚定的阶段一已完成真实复验，仍需覆盖超长文档、跨页表格和跨段冲突；
- 实体规范化基础表和人工 CLI 已完成；模型候选导入、实体合并复核、知识图谱投影，以及更广泛的语义冲突识别仍未实现；
- Reranker 和全文/向量/图谱联合排序；
- OCR、NAS 增量同步、权限主体、部门审批流及其他企业级高影响 Web 写操作；
- Obsidian 手动编辑回写和并发差异检测。
- 扩充到更多真实黄金资料，并建立跨文档冲突质量基线。

这些能力必须沿用现有证据、密级、修订和审计边界，不得绕过业务层直接写 Markdown。
