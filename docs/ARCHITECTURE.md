# 第一阶段架构

## 目标

当前版本建立一个安全、可验证的知识编译内核。它不是 Obsidian 插件，也不依赖 Web 界面；未来的 Web 工作台和 Obsidian 都只通过同一业务层读取或修改状态。

## 数据流

```text
用户文件
  -> SHA-256 去重与版本识别
  -> workspace/raw/ 内容寻址只读副本
  -> 格式解析器（保留页码/标题/单元格/幻灯片/行号）
  -> 原文保真分段器（同一运行内逐字相同正文合并为多个定位）
  -> processing_runs 派生运行（解析器+版本+提取方法）
  -> SQLite 原子证据 + JSONL 可检查镜像
  -> Obsidian 兼容 Markdown Wiki 草稿
  -> 人工证据审核
  -> 页面修订审核与发布
  -> SQLite FTS5 + BGE-M3 精确余弦检索
```

## 当前安全性质

- 同一 SHA-256 不会重复创建文件版本或 Wiki 页面。
- 解析器或提取器升级时创建版本化派生运行；相同处理指纹不会重复执行，旧证据和旧修订保留审计。
- 全文检索、审核列表和向量索引只读取“文档当前版本 + 该版本当前处理运行”的证据；冲突检测可显式比较新旧版本的当前处理运行。
- 语义检索会校验当前证据指纹；派生运行变化后拒绝使用旧向量索引，直到显式重建。
- 历史文件版本或已被替代处理运行的证据和 Wiki 修订不能进入审核或发布状态。
- 文件版本或处理运行变化时，旧正式修订继续生效，但本页及引用它的已发布下游页面自动标记 `needs_revalidation` 并写入审计。
- 导入事务失败时会回滚数据库并清理本次生成的文件。
- 旧 `.doc` 默认拒绝处理；显式授权后只在临时目录转换，宏被禁用，证据定位保存转换工具、版本和转换产物哈希。
- 原文片段为空时数据库约束和业务逻辑都会阻断。
- Schema v8 以 `evidence_locations` 保存证据的全部有序来源定位，并以 `evidence.locator_json` 保留首定位兼容读；合并只发生在同一处理运行内逐字相同的正文，跨文档、跨版本和近似文本不合并。迁移只回填历史首定位，不改写证据 ID、审核状态或既有引用。
- Schema v9 以 `canonical_entities`、`entity_aliases` 和 `evidence_entity_mentions` 保存人工确认的实体规范化结果。同类型的规范化别名全局唯一；关联提及必须逐字存在于当前证据原文且匹配已登记别名。模型语义字段不会自动创建实体或合并别名，所有写操作要求 actor 并记录不含名称正文的哈希审计；错误关联可解除，历史关联随旧证据保留但不能向历史证据新增关联。
- Schema v10 以 `entity_candidates` 保存 `model_assisted` 阶段一中的实体建议。导入不调用模型，且在写入前重验分析 Schema、文件版本 SHA-256、密级、当前处理运行和逐字证据映射；相同分析文件重复导入幂等。候选只能 `pending → accepted/rejected`，接受必须由人工指定 active 规范实体，并再次确认来源仍为当前、名称逐字存在且同类型别名无歧义，随后在单一事务内写入别名、证据关联、候选终态和哈希审计。非逐字候选只可驳回或另走人工登记。
- Schema v11 以 `entity_merge_requests` 保存人工指定方向的同类型实体合并请求，不根据名称相似度自动建候选，也不允许提议人复核自己的请求。请求只能 `reviewing → merged/rejected`；批准前在事务内重验源和目标仍为同类型 active 实体，再迁移源实体的别名、证据提及和已接受候选指向，最后归档源实体。旧实体行和合并请求不删除，名称与意见只以哈希进入合并审计；别名唯一、外键或状态校验失败会整体回滚。Lint 验证 active 实体仅有一个 canonical 别名、已合并源实体不再持有别名/提及/候选指向，以及双人分离和合并投影完整性。
- 相似实体候选是 SQLite 上的纯查询投影，不新增候选表、不写审计，也不触发合并请求。投影仅使用 active、同类型实体的人工别名，按规范化三字符片段建立倒排块后计算最佳 `SequenceMatcher` 相似度；高频块和比较对数均有硬上限，并在结构化统计中暴露跳过、截断和已有人工合并请求状态。候选只表示名称接近，不能证明实体相同，必须由人工另行执行 `merge-propose`。
- 实体 Web 可见性不是可人工覆盖的第二套密级字段，而是从全部历史 `evidence_entity_mentions` 支持实时取最高资料密级；即使旧证据已不是当前运行，restricted 历史支持仍使实体保持 restricted。没有任何证据支持的 active 实体为 `unclassified`。Web 实体选择只投影 public、internal、confidential，排除 restricted、unclassified 和 archived；写适配器在接受模型候选前按目标实体 ID 再次重算，防止绕过列表直接提交隐藏实体。
- 实体图谱当前是纯查询投影，不建立第二套图数据库或关系真相。节点来自 active 规范实体；`co_occurs_in_atomic_evidence` 边仅由同一当前原子证据中的人工确认提及确定，携带支持证据 ID、证据状态和密级集合，不能解释为业务关系。默认只使用 verified；显式审核模式可加入 draft、reviewing 和 conflicted，但 deprecated、archived 与 restricted 无条件排除。投影不返回原文、不写数据库、不提供文件导出，文件版本或处理运行变化会使旧支持自动退出。
- Schema v12 以 `entity_relation_types`、`entity_relationships` 和 `entity_relationship_evidence` 保存人工定义的业务关系真相。关系类型明确有向/无向；登记关系必须引用至少一条当前 verified 证据，且每条证据都已通过 `evidence_entity_mentions` 人工确认同时逐字提及两个 active 端点。无向端点按 ID 规范化，active 关系按类型与方向唯一；关系只允许 `active → retracted`，撤销不删除证据或历史，登记与撤销说明只保存 SHA-256。模型候选、共现投影和相似度候选均不能自动写入业务关系。
- `manual-business-relationships-v1` 是业务关系的只读安全投影，只返回仍有当前 verified 非 restricted 支撑的 active 边及证据 ID，不返回原文。文件版本或证据状态变化会让过期支撑退出投影而不改写历史；Lint 对没有当前 verified 支撑的 active 关系给出待复核警告，并校验所有历史支撑仍同时关联两个端点。为避免语义被无声改写，已被任何关系历史引用的端点提及不可解除；实体合并在源实体存在任何业务关系历史时阻断，而不是迁移或重写旧关系。
- 图谱黄金评测只接受异人复核批准的数据集，数据集不保存原文。评测前逐项确认实体仍为 active，黄金证据仍是当前 verified 非 restricted；任何来源漂移都会整体阻断。报告分别计算关系存在性、方向、证据覆盖和受限深度路径指标，并独立报告 restricted 支撑泄漏数；多跳路径只按明确标注的实体、关系和遍历方向匹配，不将可达性提升为业务事实。
- `draft` 证据不能跳过 `reviewing` 直接变成 `verified`。
- 页面发布前必须至少引用一条证据，且所有引用证据都是 `verified`；核心发布函数在事务内再次校验 Markdown 路径和内容哈希。
- 已发布页面的新资料生成新修订，不覆盖当前已验证修订。
- `internal` 云调用需要单次授权；更高密级无条件禁止云调用。
- 模型调用审计只保存模型、密级、耗时和输入输出哈希，不保存提示词明文。
- 阶段二不能仅用一个真实证据ID包装无关结论；结论与全部所引原文均缺乏最低文本关联时Schema校验阻断，弱关联继续交给人工复核；高相似引用中的方向或关键数字矛盾同样阻断。
- DeepSeek 阶段二 `wiki-generation-v2-extractive` 提示词只允许单条证据的逐字抽取式结论，禁止改写、多证据综合及原文未明确陈述的因果、主体、条件、时间、范围、义务、许可、禁止、比较或数值推断；无法逐字表达的内容进入人工任务。该提示词约束不替代阶段二既有的 Schema、引用 ID、文本支撑、方向词和关键数字硬校验。
- DeepSeek 阶段一 `analysis-v3-source-anchored` 不让模型决定证据身份、正文或定位。本地先用 `FaithfulEvidenceExtractor` 生成有序 `candidate_id`、逐字 excerpt 和全部定位，模型只对这份固定清单补充证据类型、实体、概念、项目和适用范围；返回后本地按 `candidate_id` 强制覆盖 excerpt、首定位和 `locators[]`，未知 ID 直接阻断。因此模型改写正文或伪造、遗漏、删减定位均不会进入分析产物，表格、段落、`unit`、`segment` 和同文多位置只来自确定性解析层。
- 新旧版本出现允许/禁止方向或关键数值变化时按证据对进入冲突队列。
- 跨文档冲突候选只用于构建人工质量基线，不自动写入冲突队列或改变证据状态。候选包排除 `restricted`，只能写入 `workspace/evaluations/` 且不得覆盖；候选身份不包含可编辑标签和复核字段。标签提交和固化都会重查当前文件版本、当前处理运行、原文、密级、文档元数据和全部定位；固化还校验已审计标签摘要、完整候选集和标注/复核人员分离。
- 任务租约绑定 `lease_owner`；非领取者不能续租、完成或报告失败，过期领取者也不能迟交结果。长任务由心跳续租；工作者失联后，过期租约会清除所有者并回到重试队列，达到最大次数才进入 `failed`。
- 持续工作器空闲轮询采用有上限的指数退避，收到停止信号后等待当前任务完成；启动、停止原因和本次处理统计写入审计。租约续期失败时工作器停止领取新任务，避免在失去所有权后继续并发处理。

## 存储真相

- SQLite 是业务状态、审核状态和审计状态的唯一真相。
- `workspace/raw/` 是内容寻址的来源副本。
- `workspace/evidence/*.jsonl` 按派生运行保存，便于人工检查和迁移，不负责状态流转。
- 分析 JSON、证据 JSONL、Wiki 草稿、标注候选和 Web 详情均投影全部定位；`lint` 同时验证定位非空、序号连续、首定位兼容字段、分析/镜像一致性、规范实体 canonical 别名、实体提及逐字回源，以及已接受模型候选是否确有对应别名和证据关联。
- `workspace/wiki/` 是 Obsidian 可读产物；手动编辑需要在后续里程碑加入回写和差异保护。
- `workspace/index/` 是可重建派生数据，可随时由 SQLite 证据重新生成。
- `workspace/evaluations/` 保存可重复比较的质量评测报告。
- `labeling-pack` 只从当前证据生成均匀分布的人工定位候选，不会自动把系统输出认定为黄金答案。
- `lint` 对现代处理运行执行严格产物验收；迁移前尚不存在的分析/生成产物显示为可见警告，不会使用来源不一致的文件冒充通过。
- Schema v6 将黄金标注保存为 `draft → reviewing → approved` 状态；提交人与复核人必须不同，每个用例均需由最终批准人逐项通过，批准后才能导出正式评测集。
- 标注证据必须属于当前文件版本和当前处理运行；来源文件、密级或处理状态变化会使未导出的标注失效。
- 冲突评测报告只输出用例ID、预期/预测类型和指标，不复制旧证据与新证据原文；真实内部冲突数据集应保存在 `workspace/`。
- 跨文档候选使用稳定字符片段阻塞后再计算文本相似度，避免直接全量笛卡尔比较；候选包同时保留预测为冲突和相似但未判冲突的证据对，供人工标注真阳性与负例。被 `--limit` 截断的包不能固化为完整召回率基线。
- Web 列表 API 不返回来源路径、原始副本路径、评测集路径、证据原文或通用审计详情；审核队列按证据、冲突和 Wiki 修订独立分页，各队列只接受自身有效状态，并只按安全元数据筛选和搜索；`restricted` 原文件名与页面标题不参与搜索。实体候选另按 `pending`、`accepted`、`rejected` 投影安全元数据，所有 `restricted` 候选都在 SQL 边界排除，不向浏览器返回候选名、证据原文或路径。单条证据原文只在显式详情请求中返回，`restricted` 名称、定位、原文和状态写入始终阻断。
- `rejected` Wiki 修订不重新进入待办队列；独立只读历史投影可展示非受限修订的领域复核意见、操作者、驳回时间及来源是否仍为当前版本，但不返回 Markdown、文件路径或原始审计详情，也不提供任何重新流转操作。`restricted` 历史标题和复核意见脱敏。
- Web 证据、冲突、实体候选、实体合并、人工业务关系与 Wiki 修订提交、驳回和正式发布操作必须提供 actor，并使用进程级 CSRF 令牌、JSON Content-Type、同源和 Host 校验；业务写入只委托给既有状态机，继续产生原有审计事件。实体候选接受必须显式选择已有 active 且 Web 可见的规范实体；目标可见性由全部历史证据的最高密级实时推导，列表查询和写适配器各校验一次。随后 `entity_candidates.py` 重新校验候选仍为 pending、来源当前、名称逐字存在、别名唯一，再原子登记别名、证据关联、终态与审计；Web 不创建规范实体，也不建立第二套写入规则。实体候选驳回意见必填，`restricted` 候选即使已知 ID 也拒绝 Web 写入。实体合并 Web 列表和写适配器分别重算源、目标实体可见性，只允许两个 public/internal/confidential active 实体；提议必须指定方向并填写说明，批准或驳回必须异人操作并填写意见，批准还要求完整输入绑定请求 ID 的确认短语。最终别名、提及、候选迁移和源实体归档仍由 `entity_merges.py` 在单一事务内完成。业务关系 Web 列表只返回两个端点都可见的关系；共同证据候选只返回当前 verified 非 restricted 的 ID、资料名和密级，不批量返回原文。登记和撤销分别要求绑定关系类型/端点或关系 ID 的确认短语，写适配器重算端点可见性和全部证据资格后再委托 `entity_relationships.py`；关系类型管理仍保留 CLI 边界。Wiki 修订操作前额外校验当前文件版本、当前处理运行和 Markdown 内容哈希；外部未同步编辑必须阻断。`reviewing → rejected` 必须附带复核意见，驳回新修订不改变旧正式修订。Web 正式发布还要求非 `restricted`、至少一条引用、引用全部验证、预览覆盖全文，并完整输入绑定修订 ID 的确认短语；后端重新计算资格，截断预览的长修订只能经 CLI 发布。
- Web 跨文档候选服务按 `pack_id` 在 `workspace/evaluations/` 发现通过 Schema 与身份校验的候选包，不向浏览器返回文件路径。详情读取和每次写入均重验当前证据来源；写入还在进程锁内比较客户端所见文件 SHA-256，原子替换 JSON，并在审计失败时恢复原内容。标签摘要一经提交即锁定，若文件标签与最新提交摘要漂移则整个 Web 写链路阻断；只有不同 actor 可复核，驳回意见必填。逐项审计保存候选 ID、决定、文件前后哈希和意见哈希，不保存原文或意见正文。Web 不自动创建业务冲突，也不固化最终评测集。
- Web 服务只允许监听 `127.0.0.1` 或 `localhost`，拒绝非本机 Host 以防 DNS rebinding；静态页面不调用外部 CDN，并设置 CSP、禁止嵌入、禁止缓存和禁止引用来源泄露等响应头。
